# 界面架构特性

Compose 导航、IME 整体 Compose 化与同框重启判定的相关特性。界面形态的现状见 [界面架构.md](../../界面/界面架构.md)，本页只登记特性与归属。

## Compose 导航与设置 UI

采用 miuix 与 miuix-nav。

- 导航壳 `ui/main/compose/AppRoute.kt` 与 `FcitxComposeApp.kt`；首页 `HomeScreen.kt`。
- 设置渲染器 `ComposeManagedPrefsScreen.kt`、`ComposeRawConfigScreen.kt`、`RawConfigHostScreen.kt`。
- 旧 Fragment 页的桥接 `LegacyScreen.kt` 与 `LegacyGraph.kt` 已移除。
- RawConfig 行形态判定抽到纯逻辑 `settings/RawConfigRowModel.kt`（`specOf`、`externalActionOf`、`RawConfigValue`，按 descriptor 判类型）。

## IME 软键盘 Compose 化

外层由 `input/LifecycleInputMethodService.kt` 挂 owner 链到 IME `decorView`，`FcitxInputMethodService.createComposeInputView()` 返回宿主。

- 宿主形态：`FrameLayout`，`InputView` 直接作子 View，覆盖层 `ComposeView` 压其上。`themeState`、`recreateNonce`、`stylusUiActive` 由 `syncHostedInputView()` 在组合期同步重建。
- 不用 `AndroidView` 承载整棵键盘树，互操作会给每帧多测一遍布局。
- 冷启动分阶段计时 `input/ColdStartTrace.kt`，kotlin-reflect 描述符预热 `input/ReflectionPrewarm.kt`。
- 各窗口的完整实现清单见 [界面架构.md](../../界面/界面架构.md#已-compose-化的组件)。
- 颜色统一走 `MiuixTheme.colorScheme`；View 侧与主键盘键面走 fcitx `Theme` 桥 `keyboard/KeyboardVisuals.kt`。

## 同框重启输入连接

`input/EditorKey.kt` 是单一真源（internal）：按 pkg、fieldId、inputType、hintText、imeOptions 判「同框 resync」与「换框」，不含 initialSel。

消费方为 `InputView.startInput`、`KeyboardWindow.onStartInput`、`VoiceInputComponent`、`StylusHandwritingController.onStartInput`。`InputView` 打日志 `startInput: restarting, sameEditor, key`。

`onStartInputView` 的 `restarting=true` 可能来自焦点换框，也可能来自同一输入框被应用 resync 重启（实测 `io.legato.kazusa` 在文本或选区被改动后会重启）。`restarting=false` 表示新会话，行为不变。`FcitxInputMethodService.onStartInput` 另打 pkg、fieldId、inputType。

同框保留 Picker、剪贴板、展开候选的当前面板；跨框才按「焦点变化时重置键盘」偏好回主键盘。
