本仓库 `custom` 分支的协作规则。分支模型决定改动落在哪里，防冲突约定决定改动怎么落，注释边界决定代码里能写什么。

## 分支与远程模型

- `origin` 是个人 fork（`xzy-nine/fcitx5-android`）；`upstream` 是官方仓库（`fcitx5-android/fcitx5-android`），其默认分支是 **master**，不是 main。
- 本地 `main` 只是上游快照，**不在 main 上开发**；所有开发都在 `custom`。
- 同步上游：`git fetch upstream && git checkout main && git merge upstream/master && git checkout custom && git merge main`。冲突时优先保留 custom 侧的环境适配补丁。
- 向 upstream 提交时不夹带 custom 私有改动。gitee 镜像、Windows 补丁、广播功能均为 fork 私有。

## 防冲突硬性约定

1. **新增字符串写入 `res/values*/custom_strings.xml`，颜色写入 `custom_colors.xml`。** 禁止加进上游的 `strings.xml` / `colors.xml`；Android 会自动合并多文件同名资源。新语言翻译放对应 `values-xx/custom_strings.xml`。
2. **对上游高频改动的文件只允许追加式小锚点**，逻辑体放新文件，模式参考现有 `*Ext.kt` / `Navigator` / `Math.kt`。UI 文件不受此条限制。
3. **新 AIDL 方法追加在接口末尾**；Manifest 的 permission/service 追加块放在既有条目之后。
4. **新设置项定义在 `AppPrefs` 对应 inner class 内**（框架约束），用 `init {}` 块集中注册并放在类尾部；分组渲染走 `PreferenceGroupUi.kt`，不重写 `createUi` 主体。
5. **改完执行 `git diff main -- <上游文件>` 自查。** 预期只剩少量追加行，资源文件应零差异。
6. **新增功能尽量放独立文件**，在原文件只留一到两行调用锚点。UI 文件的合并冲突同样以 custom 侧为准。

## 注释内容边界

注释只写代码功能、可执行约束与不变量。以下内容一律不写入注释。

| 禁止内容 | 示例 |
|---|---|
| 厂商品牌名 | 米系、搜狗、讯飞、Gboard |
| 反编译产物标识 | `.java` 类名 |
| 仓外本地路径 | 个人机器路径 |
| 功能变更史 | 「之前出过 X bug」「已移除 Y」 |

## 分支内文件职责

`AGENTS.md` 只存在于 `custom` 分支，上游没有这个文件，合并上游时务必保留。每次 custom 新增 feature 后按 [custom特性.md](README.md) 的格式登记条目；bug 与 fix 不登记在特性表里。
