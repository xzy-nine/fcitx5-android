# 测试策略

本仓库的测试分层、执行入口与证据选择。命令见 [构建与验证.md](构建与验证.md)。

## 分层

| 层 | 位置 | 规模 | 运行方式 |
|---|---|---|---|
| JVM 单元测试 | `app/src/test/java/org/fcitx/fcitx5/android/` | 282 个文件 | `./gradlew :app:testFxDebugUnitTest` |
| 仪器测试 | `app/src/androidTest/java/org/fcitx/fcitx5/android/` | 21 个文件 | 需设备或模拟器，`:app:assembleFxDebugAndroidTest` 编译，`connectedFxDebugAndroidTest` 执行 |
| 性能探针 | `tools/input-perf/` | 见 [性能诊断.md](性能诊断.md) | 需显式授权的测试 AVD |

JVM 单元测试的依赖包含 JUnit、Robolectric 4.17、MockWebServer、okhttp-tls、work-testing。`unitTests` 配置打开了 `returnDefaultValues`，使经 `android.util.Log` 打日志的代码可在 JVM 下运行；Robolectric 用于依赖 Android 框架行为的回归，parser 与 validator 用桩。

## CI 执行

| 工作流 | 测试命令 |
|---|---|
| `ci.yml` | `:app:testFxDebugUnitTest` |
| `pr.yml` | `:app:testFxDebugUnitTest`，另跑 `:app:compileFxDebugAndroidTestKotlin` 保证仪器测试可编译 |
| `direct-rime.yml` | `:app:testFxDebugUnitTest`，原型路径另跑 `:direct-rime:testDebugUnitTest` |

性能类工作流（`fcitx-direct-perf`、`rime-candidate-perf`、`wanxiang-perf` 等）只编译 `assembleFxDebugAndroidTest`，不执行会准备测试方案的探针。

## 证据选择

按改动面选最小充分证据，不要反射性地跑全量。

| 改动 | 最小证据 |
|---|---|
| 纯逻辑（布局计算、词库合并、预处理） | 该包下的单元测试 |
| 偏好、默认值、迁移 | 对应 `data` 包单元测试与 `UserDataBackupSnapshotTest` |
| Compose 组件 | 该组件的图形单测；涉及渲染缺陷时补设备验证 |
| 引擎桥接、进程边界、触控笔 | 对应仪器测试与设备验证 |
| 文档、Agent Note | `npm run test:docs` |
| 门禁脚本 | 该脚本的单元测试，加一次故意违规的负向验证 |

截图与图形单测不替代输入与保存功能测试；实际窗口、键盘、触摸与返回行为使用设备验证，并分别记录来源与限制。

## 测试基础设施

`app/src/test/java/org/fcitx/fcitx5/android/testing/` 提供共用夹具。新增测试优先复用，不要为单个用例复制断言辅助。

Android 变体的 QuickJS 只带 `.so`，桌面 JVM 单测无法加载，相关契约测试改走变体运行时类路径。
